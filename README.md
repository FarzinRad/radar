# رادار · هشدار آب‌وهوای خطرناک ایران

داشبورد سینمایی (همان دمو) با **داده‌ی زنده و رایگان** از Open-Meteo، به‌علاوه‌ی **کارت هشدار متحرک** («چه کنم؟» + صحنه‌ی شهر + میزان خطر) که خودکار به تلگرام، بله، ntfy، X و اینستاگرام می‌رود، یا از روی گوشی با یک دکمه برای دوستانت می‌فرستی.

همه‌چیز روی GitHub رایگان اجرا می‌شود: GitHub Actions داده را هر ۳ ساعت می‌گیرد و هشدار می‌فرستد، GitHub Pages سایت را میزبانی می‌کند. سرور، کارت بانکی و هزینه لازم نیست.

> پیش‌بینی مدل است، نه هشدار رسمی. هر کارت و پیام این را می‌گوید.

## چه چیزی ساخته شده

| بخش | کجا | چه می‌کند |
| --- | --- | --- |
| داشبورد | `web/index.html` + `web/js/app.js` | نقشه‌ی ۳۱ استان، ۱۷۵ شهر، خط زمان ۲۴ ساعت گذشته تا ۷۲ ساعت آینده، سوییچ مدل (IFS · AIFS · GFS · ICON · اجماع)، میدان بارش واقعی، ذرات باد واقعی، صاعقه از CAPE، گردوغبار از CAMS، ردیابی سامانه‌ها، کارت شهر با حکم «چه کنم»، کارنامه‌ی مدل‌ها (هنوز نمونه‌ی ساختگی) |
| کارت هشدار | `web/card.html` + `web/js/card.js` | تصویر ۱۰۸۰×۱۳۵۰ (پست) یا ۱۰۸۰×۱۹۲۰ (استوری): سطح خطر، صحنه‌ی متحرک شهر (آب، برف، باد، صاعقه، گردوغبار)، نوار میزان خطر، «چه کنم؟»، زمان رسیدن، نقشه‌ی کوچک ایران |
| پایپلاین | `pipeline/radar/` | دریافت از Open-Meteo → سطح خطر هر ساعت با آستانه‌ی محلی هر شهر → ردیابی سامانه‌ها → تشخیص هشدار → ساخت PNG و MP4 → ارسال |
| زمان‌بندی و استقرار | `.github/workflows/radar.yml` | هر ۳ ساعت، به‌علاوه‌ی اجرای دستی با «شهر آزمایشی» |

حالت نمایشی دمو هنوز هست: `?demo=1` را ته آدرس بگذار.

## ربات: هر دوست شهر یا روستای خودش را انتخاب می‌کند

دوستت لینک دعوت (`https://t.me/<اسم ربات>?start=<کد دعوت>`) را باز می‌کند، اسم شهر یا روستایش را می‌نویسد یا از دکمه‌ها انتخاب می‌کند، و از آن به بعد هر هشدار نارنجی یا قرمز همان‌جا برایش می‌آید.

| فرمان | کار |
| --- | --- |
| نوشتن اسم شهر یا روستا | اضافه کردن (تا ۸ محل) |
| `/now` | وضعیت الان محل‌های من |
| `/list` · `/stop رشت` · `/stop` | فهرست · حذف یکی · حذف همه |
| `/daily` | روشن یا خاموش کردن گزارش صبحگاهی |

- **۱۷۵ شهر اصلی** (همه‌ی مراکز استان و شهرهای مهم) همیشه روی نقشه و در داده‌اند.
- **هر شهر یا روستای دیگر** (از حدود ۱۸۰۰ شهر و هزاران روستای GeoNames) فقط وقتی کسی دنبالش کند، جدا پیش‌بینی می‌شود. هزینه‌اش به تعداد مشترکان بستگی دارد، نه به تعداد شهرهای ایران. اسم این محل‌ها هیچ‌وقت در سایت، artifact یا لاگ عمومی نمی‌آید و هشدارش فقط برای خود مشترک می‌رود.
- **فهرست مشترکان** رمزنگاری‌شده در `state/subscribers.enc` است (کلید: Secret به نام `BOT_STATE_KEY`). مخزن عمومی است ولی شناسه‌ی چت و محل دوستانت خوانا نیست.
- **کد دعوت:** با Secret به نام `BOT_INVITE_CODE`، فقط کسی که لینک دعوت را دارد می‌تواند عضو شود.
- **سرعت جواب:** ربات سرور ندارد و هر ۱۵ دقیقه پیام‌ها را می‌خواند، پس جواب تا ۱۵ دقیقه طول می‌کشد. خود هشدارها منتظر این نمی‌مانند و با اجرای اصلی می‌روند. ویدیو فقط یک بار آپلود می‌شود و برای بقیه‌ی چت‌ها همان فایل دوباره فرستاده می‌شود.

## دو راه هشدار دادن به دوستان

1. **خودکار:** وقتی سطح یکی از شهرهای `pipeline/watch.json` یا شهرهای مشترکان ربات به نارنجی یا قرمز برسد، ربات یک ویدیوی ۸ ثانیه‌ای کارت + متن «چه کنم» را به گروه‌های تلگرام یا بله و به مشترکان همان شهر می‌فرستد. اگر خطر رفع شود، پیام «رفع خطر» می‌آید. ساعت ۰۰ تا ۰۷ فقط قرمز ارسال می‌شود. صبح‌ها (۰۶ تا ۰۹) یک گزارش کشوری هم می‌آید.
2. **دستی از گوشی:** در داشبورد روی شهر بزن، بعد «📣 هشدار برای دوستان». «اشتراک ویدیو» یا «اشتراک عکس» منوی اشتراک گوشی را باز می‌کند و مستقیم می‌شود به **استوری اینستاگرام با Close Friends**، تلگرام، بله، واتس‌اپ یا X فرستاد. لینک `card.html?city=تهران` را هم می‌شود مستقیم برای کسی فرستاد.

> API اینستاگرام اجازه‌ی انتخاب Close Friends را نمی‌دهد. برای حلقه‌ی نزدیک، راه ۲ (اشتراک از گوشی) یا گروه تلگرام و بله بهتر است. ارسال خودکار به اینستاگرام و X عمومی است.

## اجرای محلی

```bash
cd pipeline && uv venv .venv && uv pip install -p .venv/bin/python -r requirements.txt
```

```bash
cd pipeline && .venv/bin/python -m radar.ingest --test-city تهران
```

```bash
python3 -m http.server 8765 --directory web
```

بعد `http://localhost:8765` را باز کن. برای ساخت عکس و ویدیوی هشدار آزمایشی (یک بار `.venv/bin/python -m playwright install chromium` لازم است):

```bash
cd pipeline && .venv/bin/python -m radar.render
```

تست‌ها: `cd pipeline && .venv/bin/python -m pytest -q tests`

## استقرار روی GitHub (یک بار، حدود ۱۵ دقیقه)

1. در GitHub یک مخزن **عمومی** بساز، مثلاً `radar` (Actions برای مخزن عمومی نامحدود و رایگان است).
2. این پوشه را push کن:
   ```bash
   cd radar && git init -b main && git add . && git commit -m "radar" && git remote add origin https://github.com/<نام‌کاربری>/radar.git && git push -u origin main
   ```
3. **Settings › Pages › Source** را روی **GitHub Actions** بگذار.
4. **Settings › Actions › General › Workflow permissions** را روی **Read and write** بگذار.
5. Secretهای کانال‌ها را طبق جدول پایین در **Settings › Secrets and variables › Actions** اضافه کن (هر کدام اختیاری است).
6. در تب **Actions**، workflow «radar» را با **Run workflow** اجرا کن. در فیلد شهر آزمایشی بنویس `تهران` تا یک هشدار آزمایشی (با برچسب «آزمایشی») به کانال‌هایت برود.
7. سایت: `https://<نام‌کاربری>.github.io/radar/`. روی گوشی «Add to Home Screen» بزن تا مثل اپ باز شود.

اگر سایت را روی دامنه‌ی دیگری می‌خواهی، متغیر `PUBLIC_BASE_URL` را در **Variables** بگذار؛ لینک‌های پیام‌ها از آن ساخته می‌شوند.

### کانال‌ها و Secretها

| کانال | Secret | چطور بگیری |
| --- | --- | --- |
| ربات (لازم برای اشتراک) | `BOT_STATE_KEY` | یک رشته‌ی تصادفی طولانی (`openssl rand -hex 32`). اگر گمش کنی، فهرست مشترکان از دست می‌رود. |
| | `BOT_INVITE_CODE` | اختیاری؛ یک کلمه‌ی رمز کوتاه برای لینک دعوت. |
| تلگرام | `TELEGRAM_BOT_TOKEN` | در تلگرام به `@BotFather` پیام بده، `/newbot`، توکن را کپی کن. |
| | `TELEGRAM_CHAT_IDS` | یک گروه با دوستانت بساز، ربات را اضافه کن و یک پیام در گروه بفرست. بعد `TELEGRAM_BOT_TOKEN=... python -m radar.notify --whoami` شناسه‌ی گروه (عدد منفی) را نشان می‌دهد. چند شناسه را با کاما جدا کن. کانال هم کار می‌کند (ربات باید ادمین باشد). |
| بله | `BALE_BOT_TOKEN`، `BALE_CHAT_IDS` | در بله به `@botfather` پیام بده؛ API هم‌شکل تلگرام است. برای دوستانی که بدون فیلترشکن پیام می‌خوانند. |
| ntfy | `NTFY_TOPIC` | یک رشته‌ی تصادفی (`openssl rand -hex 12`). در اپ ntfy همین topic را subscribe کن؛ به دوستانت هم بده. |
| X | `X_API_KEY`، `X_API_SECRET`، `X_ACCESS_TOKEN`، `X_ACCESS_SECRET` | در developer.x.com یک App بساز، دسترسی **Read and write** بده، Access Token بساز. سطح رایگان X محدودیت ارسال ماهانه دارد و ممکن است تغییر کند. |
| اینستاگرام | `IG_USER_ID`، `IG_ACCESS_TOKEN` | حساب باید Professional و وصل به یک صفحه‌ی فیسبوک باشد؛ از یک App در developers.facebook.com با دسترسی `instagram_content_publish` توکن بلندمدت بگیر. `IG_MODE` (متغیر) می‌تواند `story`، `reel` یا `feed` باشد. اینستاگرام فایل را از آدرس عمومی سایت برمی‌دارد. |

### تنظیمات (Variables، اختیاری)

| متغیر | پیش‌فرض | معنی |
| --- | --- | --- |
| `ALERT_MIN_LEVEL` | `2` | از چه سطحی هشدار برود (۲ نارنجی، ۳ قرمز) |
| `ALERT_MAX_MEDIA` | `4` | حداکثر ویدیو در هر اجرا |
| `ALERT_HORIZON_H` | `24` | هشدار برای خطرهای چند ساعت آینده (تا ۷۲) |
| `DAILY_REPORT` | `1` | گزارش صبحگاهی کشور |
| `DAILY_CHANNELS` | `telegram,bale,ntfy` | گزارش صبحگاهی کجا برود |
| `CLIMATE_BUDGET` | `1500` | سهم روزانه‌ی ساخت اقلیم ERA5 |

شهرهای هشدار در `pipeline/watch.json` است؛ شهر دوستانت را اضافه کن (اسم باید دقیقاً مثل `pipeline/cities.json` باشد).

## داده‌ها کجا ذخیره می‌شوند

| داده | کجا |
| --- | --- |
| آخرین پیش‌بینی همه‌ی شهرها | `data/latest.json` روی سایت؛ هر ۳ ساعت تازه می‌شود. هر برنامه‌ای می‌تواند بخواندش (API فقط‌خواندنی). |
| آرشیو پیش‌بینی‌ها | شاخه‌ی `data` همین مخزن، `forecasts/سال/ماه/*.json.gz`؛ اجراهای ۰۰ و ۱۲ UTC، کمتر از ۴۰ مگابایت در سال |
| حقیقت زمینی (ERA5) | شاخه‌ی `data`، `truth/`؛ هر هفته یک بار، بعد از نهایی شدن |
| کارنامه‌ی هفتگی | `scorecard.json` در شاخه‌ی `data` و روی سایت؛ شنبه‌ها حدود ۷ صبح تهران ساخته می‌شود |
| وضعیت هشدارها، مشترکان (رمزشده)، اقلیم | پوشه‌ی `state/` و `pipeline/climate.json` در شاخه‌ی اصلی |

کارنامه برای هر هفته جمع خطاها و تعداد نمونه‌ها را نگه می‌دارد، نه میانگین، تا جمع چندهفته‌ای درست باشد. هفته‌ای که ERA5 هنوز کاملش نکرده «موقت» است و اجرای بعدی نهایی‌اش می‌کند.

## منطق خطر، خلاصه

- **باران:** مجموع ۶ ساعت آینده در برابر ۰٫۶ آستانه‌ی ۲۴ ساعته‌ی **همان شهر**. آستانه‌ها صدک ۹۰، ۹۵ و ۹۹ بارش روزهای بارانی در ۱۰ سال ERA5 است (`pipeline/climate.json`، روزی چند شهر ساخته می‌شود؛ تا آن موقع از نرمال استان تخمین زده می‌شود و کارت شهر این را می‌گوید).
- **برف:** ۳، ۸ و ۱۵ سانتی‌متر (بالای ۱۵۰۰ متر: ۵، ۱۲ و ۲۰). **باد:** تندباد ۵۵، ۷۵ و ۹۵ km/h. **رعدوبرق:** CAPE ≥ ۸۰۰ همراه بارش. **گردوغبار:** PM10 برابر ۱۵۵، ۲۵۵ و ۳۵۵ میکروگرم.
- **اجماع:** میانگین ساعتی چهار مدل. **ETA:** سهم مدل‌هایی که به نارنجی می‌رسند، با بازه‌ی صدک ۱۵ تا ۸۵؛ زیر ۲۰٪ یعنی «احتمالاً نمی‌رسد».
- منطق فقط در `pipeline/radar/hazards.py` است و تست دارد؛ فرانت همان سطح‌ها را از `latest.json` می‌خواند.

## محدودیت‌های صادقانه

- Open-Meteo فقط برای استفاده‌ی **غیرتجاری** رایگان است (حدود ۱۰ هزار فراخوانی در روز). این پایپلاین حدود ۸ تا ۹ هزار مصرف می‌کند؛ اگر شهر اضافه می‌کنی، فاصله‌ی cron را بیشتر کن.
- رانرهای GitHub آدرس IP مشترک دارند؛ اگر Open-Meteo موقتاً جواب ندهد، سایت داده‌ی قبلی را با برچسب «داده‌ی کهنه» نشان می‌دهد.
- میدان نقشه از یک مدل (IFS) و روی شبکه‌ی ۲ درجه است؛ عددهای شهرها از هر چهار مدل می‌آیند.
- WeatherNext 3، ماهواره و رعدوبرق Blitzortung هنوز وصل نیستند (P1 در PRD).
- کارنامه‌ی مدل‌ها از اولین هفته‌ی کامل بعد از استقرار واقعی می‌شود؛ تا آن موقع صفحه‌اش نمونه‌ی ساختگی را با برچسب نشان می‌دهد.
- cron گیت‌هاب ممکن است چند دقیقه دیر شروع شود. اگر ۶۰ روز هیچ commitی نباشد، GitHub زمان‌بندی را خاموش می‌کند؛ workflow روزی یک بار `state/last_run.txt` را commit می‌کند تا این اتفاق نیفتد.
- `github.io` معمولاً از داخل ایران باز می‌شود ولی تضمینی نیست. اگر نشد، پوشه‌ی `web` را می‌شود بدون تغییر روی Cloudflare Pages یا Netlify هم گذاشت.
